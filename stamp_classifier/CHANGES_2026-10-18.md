# stamp_classifier 変更記録（2026-10-18）

fink と fink2 の real/bogus 分類（SimCLR ＋能動学習）の挙動の違いを調べ、その結果にもとづいて fink2 の学習・評価・候補選択を変更した記録です。

## 1. 背景と調査結果

### きっかけ
fink では、能動学習でラベルを増やすほど real_pos / real_neg / bogus の境界が明確になっていく印象があった。fink2 では、ラベルを 700 件まで増やしても RF の精度が約 0.76 で頭打ちになっていた。

### 主な調査結果
1. **SupCon は飽和していたが、汎化にはつながっていなかった**
   - 学習履歴の SupCon loss は epoch 1 から約 3.91 で横ばいだった。これは、クラス比とバッチサイズから決まる理論的な下限とほぼ同じ値。
   - 学習に使ったラベルに対する精度は 0.999、天体単位の CV では約 0.75 だった。ラベル付きデータを暗記しているだけで、未知のデータには汎化していない。
2. **SupCon の入れ方を変えても、入れなくても、holdout 精度は変わらなかった**（25 epoch、同じ holdout 138 件で比較）

   | 方式 | 最後の 5 epoch の平均：RF acc / bacc | RF bacc の最大値 |
   |---|---|---|
   | 純 SimCLR（ラベル不使用） | 0.714 / 0.705 | 0.728 |
   | separate（従来の SupCon） | 0.716 / 0.709 | 0.738 |
   | mixed（新方式の SupCon） | 0.700 / 0.670 | 0.723 |

   - 3 方式の差は、holdout の標準誤差（約 ±0.04）の範囲内。
   - どの方式でも epoch 1 でほぼ最終的な精度に達している。
3. **fink2 のラベル集合は難しい事例に偏っている**
   - 同じ特徴量（fink の物理特徴 20 次元）でも、fink のラベル（1,500 件）では acc 0.84、fink2 のラベル（700 件）では 0.70 になる。
   - 同じ fink2 のラベルで比べると、fink2 の SimCLR 特徴（0.753）は fink の物理特徴（0.700）より良い。
   - ラベルを付けた順に 100 件ずつ見ると、CV 正解率は最初の 100 件で 0.88、最後の 200 件で 0.67〜0.68 だった。
   - fink2 は margin が最小のサンプルばかり選ぶため、ラベルを足すほど評価に使う集合が難しくなる。そのため「ラベルを増やしても精度が上がらない」ように見える。
4. **fink で「境界が明確」に見えたのは、学習に使ったサンプルを図示していたためである可能性が高い**
   - fink には holdout が無く、PCA の図に描かれているラベル付きの点は SimCLR の学習にも使われたものだった。
   - 境界の明確さが未知のデータに汎化していたかどうかは、確かめられていなかった。

### 結論
fink2 の精度が低いのは、主に「難しい事例ばかりを選ぶ能動学習」と「それを評価にも使う」組み合わせによるもので、アルゴリズムの優劣ではない。進歩を正しく測るには、能動学習とは独立にランダムに選んだ固定の評価用セットが必要。

## 2. 変更内容

### 2.1 SimCLR 学習（`train_simclr.py`、`losses.py`、`config.py`）
- **holdout 評価**
  - ラベルの 20% を `diaObjectId` のハッシュで holdout に分ける（`holdout_frac`）。ハッシュなので、ラベルを追加しても既存の割り当ては変わらない。
  - 毎 epoch、エンコーダ出力 h で kNN（コサイン距離）と RF を当てはめ、holdout の accuracy / balanced accuracy を記録する。
  - 固定の評価用セット（後述）が 30 件以上あれば、それを holdout として優先して使う。このとき学習用ラベルは全件学習に使い、評価用セットと同じ天体の学習用ラベルは除外する。
- **ベストモデルの選び方**
  - `best_simclr_encoder.pt` は、合計損失の最小ではなく holdout の RF balanced accuracy（`select_metric`）で選ぶ。
  - 最終 epoch のモデルは `last_simclr_encoder.pt` として保存する。
- **混合 SupCon（`--supcon_mode mixed`、デフォルト）**
  - `SemiSupConLoss` を新たに追加した。未ラベルとラベル付きを 1 つのバッチに混ぜて計算する。
  - 従来の方式は `--supcon_mode separate` で使える。
- **ラベル付きバッチのクラス均衡サンプリング**（`balanced_labeled`）
- **修正**
  - fp16 のオーバーフローを避けるため、損失を fp32 で計算するようにした。
  - ラベル付き画像は最初に 1 回だけ RAM に読み込む。
  - ラベルが無いときに `labeled_dataset` が未定義になるエラーを直した。
  - PCA の図はベストモデルで描くようにした。
- **出力**
  - `training_history.csv` に holdout の列を追加。
  - `loss_curve.png` に holdout 精度のパネルを追加。
  - `label_split.csv` に各ラベルの割り当て先を記録。

### 2.2 固定評価用セット（`loop_orchestrator.py`、`labeling_viewer.py`、`run_pipeline.py`）
- **`--mode build_eval_set`**
  - 埋め込みキャッシュ全体から、固定シードの乱数順に 150 件（`--eval_size` で変更可）を、モデルの予測を隠したブラインド表示で目視判定する。
  - 結果は `data/eval_labels_step1.csv` に保存する。学習用ラベルとは別ファイルで、学習にも候補選択にも使わない。
  - 学習用ラベルと同じ天体は評価用セットから除外し、逆に評価用セットと同じ天体は能動学習の候補から除外する。
  - `q` で中断しても、同じ順番の続きから再開できる。
- **`--mode evaluate`**：現在の RF を評価用セットで評価し、混同行列とクラス別の指標を表示する。
- **`active_loop`**：毎サイクル、評価用セットでの `eval_acc` / `eval_bacc` / `n_eval` を履歴に記録する。

### 2.3 候補選択（`active_sampler.py`、`config.py`）
- 1 サイクルの選択枠を fink 方式に近づけた。割合は `ActiveLearningConfig` で変更できる。

  | 枠 | 割合 | 内容 |
  |---|---|---|
  | uncertainty | 50% | margin が最小の境界事例 |
  | exploit | 15% | real（bogus 以外）の確率が高いもの |
  | anomaly | 15% | IsolationForest の異常度が高いもの |
  | random | 10% | 一様ランダム |
  | diversity | 10% | クラスタリングで選ぶ代表点 |

- uncertainty、exploit、anomaly の枠では、上位候補を KMeans で分けてから選ぶ（似たものばかり選ばないため）。
- 各ラベルに、どの枠で選ばれたかを `selection` 列として記録する。
- ラベルが無い初期段階では anomaly、random、diversity の枠だけで選ぶ。従来は DB の先頭から決まった順に選ばれていた。

### 2.4 バグ修正（`loop_orchestrator.py`）
- RF 再学習時に、キャッシュに無いラベルがあると X と y がずれていたのを直した。今は `diaSourceId` で対応付けている。
- RF の確率の列がクラスの並びとずれる問題を直した（学習時に存在しないクラスがあると起きていた）。
- 履歴 CSV は、列が増えても既存の行と整合するよう全体を書き直す方式にした。

### 2.5 層別評価用セットと重み付き評価（2026-10-19 追加、`eval_strata.py`）
- **背景**：ランダムに選んだ 200 件の評価用セットは bogus 152、positive_real 37、negative_real 11 で、母集団の比率をそのまま映していた。その結果、negative_real の recall と precision の誤差が大きかった（±0.09〜0.12）。
- **層の固定**
  - `--eval_stratum` を初めて使ったとき、その時点の RF の予測クラスで、評価対象になり得る母集団を 3 つの層に分ける。
  - 割り当ては diaSourceId ごとに `data/eval_labels_step1_strata.npz` に保存する。層を作った RF のコピーも `*_stratifier.joblib` として残す。
  - エンコーダや RF を後で更新しても、層は変わらない。
- **層の中での追加判定**
  - `--mode build_eval_set --eval_stratum negative_real --eval_size 50` で、予測 negative_real の層の評価ラベルが 50 件になるまで、層の中からランダムに判定する。
  - `--eval_size` は、その層の評価ラベルの目標件数（追加件数ではない）。そのため中断しても再開できる。
- **重み付き評価**
  - サンプル i（層 h）の重みを `w_i = N_h / n_h`（N_h：層の大きさ、n_h：層の中の評価ラベル数）として集計し、母集団に対する accuracy、balanced accuracy、クラス別の recall / precision / 有病率を推定する。
  - 既存のランダム評価用ラベルも、層の中では一様ランダムなので、そのまま重み付き集計に含まれる。
  - 標準誤差は、層の中で復元抽出を繰り返すブートストラップで求める。
  - 層ファイルがあれば、`evaluate`、`active_loop` の履歴（`eval_acc` / `eval_bacc` は重み付き値）、`eval_*_se`、クラス別の `eval_recall_*` / `eval_precision_*` が重み付きになる。重み無しの値も `eval_*_unweighted` として残す。
- **シミュレーションでの検証**：200 件のランダム抽出に、予測 negative_real から 50 件、予測 positive_real から 30 件を追加した場合（300 回の繰り返し）。
  - 重み付き推定は真値と一致した（accuracy：真値 0.899 に対し 0.900）。
  - 重み無しの推定は 0.830 と偏った。
  - 少数クラスの recall では、ブートストラップの標準誤差が実際のばらつきよりやや小さく出る（negative_real の recall：0.052 に対し実際は 0.073）。目安として扱うこと。
- **注意**：`train_simclr` でのベストモデルの選択は、今も重み無しの holdout 精度で行っている。

### 2.6 能動学習のフィードバックモード `rf_only`（2026-10-19 追加）
- `--feedback_mode rf_only`：エンコーダと埋め込みは固定したまま、新しいラベルで RF だけを再学習する。1 サイクル約 20 秒。
- `fine_tune`（デフォルト）は `best_simclr_encoder.pt` を上書きし、全件の埋め込みを作り直す。2 つのモードを評価用セットで比べ、エンコーダの微調整に効果があるかを判断する。
- 履歴 CSV に `feedback_mode` 列を追加した。
- `fine_tune` で、ラベル数を 64 で割った余りが 1 のとき BatchNorm1d がエラーになっていた問題を直した（端数のバッチを捨てる）。

### 2.7 評価用ラベルの監査（`--mode audit_eval`、2026-10-19 追加）
- 評価用ラベルの揺らぎ（判定者の自己一致率）を、ブラインド再判定で測るモード。
- **監査対象**：現在の RF が誤った評価サンプル全件と、正解したサンプルからランダムに選んだ `--audit_n_correct` 件（デフォルト 50）。
  - 2 つの群を混ぜて並べ替え、元のラベルもモデルの予測も表示しない。
  - 監査リストは初回に `data/eval_labels_step1_audit_list.csv` として固定する。中断しても同じ順で再開できる。
- 判定画面に `[u] Unsure`（判定不能）を追加した（監査モードのときだけ表示）。
- 再判定の結果は `data/eval_labels_step1_audit_labels.csv` に保存する。元の評価用ラベルは変更しない。
- **集計（`--mode audit_report` で集計だけを再実行できる）**
  - 群ごとの自己一致率、判定不能の割合、誤り群で再判定がモデルの予測と一致した割合。
  - 群の抽出率と層で重み付けした、評価用セット全体と母集団に対する自己一致率と、再判定ラベルに対するモデルの精度。
  - Cohen の κ、元のラベルと再判定の対応表。
  - サンプルごとの結果を、不一致のものから先に並べて `data/eval_labels_step1_audit_report.csv` に出力する。

### 2.8 評価用ラベルの裁定と閾値分析（2026-10-19 追加）
- **`--mode adjudicate_eval`**
  - 監査で、元のラベルと再判定が一致しなかったサンプルを 1 件ずつ表示する。画面のタイトルに「1st label = … / re-review = …」と両方の判定を表示し、最終ラベルを選ぶ。
  - 裁定結果は `data/eval_labels_step1_adjudicated.csv` に保存する。中断しても再開でき、スキップしたサンプルは次回もう一度提示される。
  - 評価用ラベルへの反映：
    - 初回の反映前に `data/eval_labels_step1.csv.bak_before_adjudication` を作る。
    - `label_orig` / `class_name_orig`（最初の判定）と `adjudicated` 列を追加し、`label` / `class_name` を最終ラベルに置き換える。
    - 反映は常に `label_orig` を起点にやり直すので、何度実行しても結果は同じ（冪等）。
- **`--mode threshold_curve`**
  - 現在の RF のスコアの閾値ごとに、母集団に対する純度・完全性・選ばれるソース数の推定値を、評価用セットの層の重みで求める。誤差は層内のブートストラップで出す（95% 区間）。
  - 対象は次の 3 つ。
    - `real`：スコア = 1 − P(bogus)
    - `positive_real`：スコア = P(positive_real)
    - `negative_real`：スコア = P(negative_real)
  - 純度 0.90 と 0.95 を満たす最小の閾値を表示する。
  - 出力は `data/threshold_curves_step1.csv`（`--out_csv` で変更可）と `models/step1/threshold_curves.png`。
  - 注意：完全性は、予測 bogus の層（約 41 万件、評価ラベル 139 件）に混ざる少数の real に強く依存する。ブートストラップの区間は実際の不確かさを小さく見積もる。

### 2.9 運用モデルの固定と閾値による判定（2026-10-19 追加）
- **`--mode freeze_model --model_version <名前> --thresholds positive_real=0.55,negative_real=0.75`**
  - 現在の `random_forest.joblib` を `models/step1/rf_<名前>.joblib` にコピーして固定する。`active_loop` で RF が学び直されても影響を受けない。
  - `models/step1/rf_<名前>.json` に次を記録する。
    - 閾値と判定ルール、作成日時、学習ラベル数
    - RF とエンコーダの md5
    - 評価用セットでの判定ごとの純度・完全性・母集団に占める割合（層の重み付き）と、`uncertain` に入ったものの真のクラスの構成
  - 同じ名前で上書きすることはできない。
- **`--mode classify_all --model_version <名前>`**
  - 固定した RF で全件を分類し、`decision` 列（`positive_real` / `negative_real` / `bogus` / `uncertain`）と `model_version` 列を追加する。
  - 出力は `data/predictions_step1_<名前>.csv`。
  - 判定ルール：
    - 閾値を超えたクラスがあれば、そのクラスに判定する（複数あれば確率が最大のもの）。
    - どれも超えなければ、閾値の無いクラス（bogus）が argmax のときは bogus、それ以外は `uncertain`。
  - 固定したあとでエンコーダが変わっている（md5 が違う）場合は警告を出す。RF はそのエンコーダの埋め込みで学習されているため。
- `classify_all` の確率の列を、RF の `clf.classes_` を使って設定のクラス順に並べ直すようにした（以前は、学習時に存在しないクラスがあるとずれる可能性があった）。

### 2.10 天体単位の集計と step2 の入力の絞り込み（2026-10-19 追加）
- **`--mode aggregate_objects --model_version <名前>`**
  - `data/predictions_step1_<名前>.csv` を天体（`diaObjectId`）ごとにまとめ、`data/objects_step1_<名前>.csv` に出力する。
  - 天体ごとの列：判定ごとのソース数、観測日数、バンド、最初と最後の MJD、各確率の最大値、real スコア（1 − P(bogus)）の最大値と平均、代表ソース（real スコアが最大のもの）。
  - 天体の判定（`object_class`）：
    - `real`：real と判定されたソースが `--min_real_sources` 件以上（デフォルト 1）
    - `uncertain`：real は足りないが、real か uncertain のソースがある
    - `bogus`：それ以外
  - real の天体には `real_type`（positive / negative / both）も付ける。
- **step2 の入力ソースの一覧**
  - `--object_classes` に指定した判定の天体（デフォルト `real,uncertain`）から、`--step2_sources` の方法でソースを選ぶ。
    - `real_uncertain`（デフォルト）：step1 で real か uncertain と判定されたソース
    - `all`：その天体の全ソース
    - `best`：天体ごとに代表 1 ソース
  - `data/step2_sources_<名前>.csv`（版付き）と `data/step2_sources.csv`（step2 が読むファイル）に保存し、作成条件を `data/step2_sources.json` に記録する。
  - 既存の `step2_sources.csv` と内容が違う場合は、`.bak_<日時>` に退避してから置き換える。
- **step2 の絞り込み**
  - `StepConfig.source_list_file` を追加した。step2 の既定値は `data/step2_sources.csv`。
  - step2 の SimCLR 学習（`pretrain` / `semi_supervised`）と埋め込み抽出（`extract`）は、このファイルにあるソースだけを使う。ファイルが無い場合はエラーにする。
  - 絞り込みを使うときは、画像キャッシュのファイル名にソース一覧のハッシュを含める。step1 の既存キャッシュの名前は変えていない。

### 2.11 天体単位の集計に検出履歴を追加（2026-10-19 追加）
- `diaSource` には受信したアラートの検出しか入っておらず、それ以前の検出はアラートに同梱された履歴（`prvDiaSources`）にしか無い。`aggregate_objects` では、両者を `diaSourceId` で重複排除して合わせ、天体ごとに次の列を加える。
  - `n_det_total`（検出回数）、`n_nights_total`（検出した夜の数）、`max_det_per_night`（1 夜あたりの最大検出回数）、`n_bands_total`
  - `first_det_mjd` / `last_det_mjd`（最初と最後の検出）、`det_duration_days`（検出期間）
  - `detection_pattern`：`multi_night`（2 夜以上）/ `single_night_multi`（1 夜だけだが 2 回以上）/ `single`（1 回だけ）
- DB は読み取りだけで使う。`prvDiaSources` は約 3.6 億行あり集計に約 9 分かかるので、結果を `data/cache/detection_history.parquet` にキャッシュする。
  - 取り込み済みファイル数（`processed_files`）と `diaSource` の行数が変わったときだけ計算し直す。
  - `--refresh_history` で強制的に計算し直し、`--no_history` で履歴を使わない。
- 学習で使う「同じ夜・同じバンドは最新の 1 件だけ」という絞り込みは、カタログを読み込む問い合わせの中だけで行っている。DB のテーブルは変更していない。

### 2.12 移動天体の候補の判定（2026-10-19 追加）
- 1 夜だけ検出された positive_real の天体の多くは、2 回の検出の間で位置が動いており（中央値 1.9 秒角、0.54 秒角/分）、小惑星などの移動天体とみられる。DB の `ssObjectId` はすべて空なので、既知の太陽系天体との対応付けでは確かめられない。
- 検出履歴に、同じ夜の最初と最後の検出の位置のずれ（`intra_night_sep_arcsec`）、時間差（`intra_night_dt_min`）、移動速度（`intra_night_rate_arcsec_per_min`）を加えた。複数の夜が該当する場合は、ずれが最大の夜の値を使う。
- `moving_candidate`：検出が 1 夜だけで、ずれが `--moving_min_sep`（デフォルト 0.7 秒角）以上、かつ速度が `--moving_min_rate`（デフォルト 0.2 秒角/分）以上のもの。
- step2 の入力からは、デフォルトで移動天体の候補を除く。含める場合は `--include_moving` を指定する。
- 履歴キャッシュに版番号（`schema_version`）を付けた。形式が変わると自動で計算し直す。

### 2.13 step2 で閾値分析を使えるようにした（2026-10-19 追加）
- `threshold_curve` の対象は step1 のクラス名に固定されていたため、step2 では空になっていた。step1 以外のクラス構成では、bogus 以外の各クラス（star / galaxy / no_host）をそれぞれ単独の対象にする（`eval_curves.targets_for`）。step1 の動作は変わらない。

### 2.14 2 クラスの境界に集中した能動学習と、天体の除外（2026-10-20 追加）
- **`active_loop --focus_classes galaxy,star`**
  - RF の確率の上位 2 クラスが指定した 2 クラスであるソースを、2 つの確率の差が小さい順に選ぶ（似たものばかりにならないよう、KMeans で分けてから選ぶ）。
  - 配分は境界 80%、ランダム 10%、多様性 10%。選んだ理由は `boundary:galaxy-star` としてラベルに記録する。
- **`active_loop --exclude_objects <CSV>`**
  - CSV に載っている天体（`diaObjectId` / `objId` / `obj_id` 列）を候補から除く。分光で確認済みの SN リストなどを、評価用にとっておくために使う。
- 分光で確認済みの SN リスト（29 天体）を `data/sn_spec_list.csv` として保存した。

### 2.15 目視判定の画面の Science / Template を asinh 表示に変更（2026-10-20 追加）
- Science と Template で共通の表示範囲（1〜99.5 パーセンタイル）を [0, 1] に規格化し、`arcsinh(10 z)` で表示する。中心を飽和させずに淡い裾野を見られる。カラーバーは元のピクセル値で表示する。
- パネルのタイトルに表示方法を出す（例：`Science (asinh)`）。Difference の表示は変えていない。
- 環境変数で変更できる：`STAMP_ST_STRETCH=linear`（従来の線形表示。上限の既定は 97 パーセンタイル）、`STAMP_ST_VMAX_PCT`（上限のパーセンタイル）、`STAMP_ST_ASINH_SOFTENING`（asinh の強さ、既定 10）。
- 対象は目視判定の画面だけ（能動学習、評価用セットの作成、監査、裁定）。モデルへの入力と PDF の画像は変わらない。

### 2.16 既存ラベルの再判定と RF の学び直し（2026-10-20 追加）
- **`--mode relabel [--relabel_target train|eval|both] [--show_previous]`**
  - これまでに付けた学習用ラベルと評価用ラベル（既定は両方）を、固定シードで混ぜて並べ、もう一度目視で判定する。
  - 既定はブラインドで、以前のラベルもモデルの予測も表示しない。`[u] Unsure`（判定不能）も選べる。
  - 判定リストは `data/relabel_step{N}_list.csv` に固定する。中断しても再開でき、結果は `data/relabel_step{N}_labels.csv` に保存する。
- **`--mode relabel_report`**：前の判定との一致率、κ、対応表を出し、サンプルごとの結果を `data/relabel_step{N}_report.csv`（変わったものから順）に出力する。
- **`--mode relabel_apply`**：再判定の結果を元のラベルファイルに反映する。
  - 初回だけ `.bak_before_relabel` のバックアップを作り、2 回目以降はタイムスタンプ付きのバックアップを作る。
  - 以前のラベルは `label_before_relabel` / `class_name_before_relabel` 列に残し、`relabeled` 列で反映済みかが分かる。
  - Unsure のサンプルはラベルファイルから外し、`data/relabel_step{N}_unsure.csv` に移す。
  - 何度実行しても結果は同じ（冪等）。
- **`--mode retrain_rf`**：目視判定はせずに、現在の学習用ラベルで RF を学び直し、評価用セットで評価して履歴に記録する。

### 2.17 母天体が点源か広がっているかを、PSF との比較で判定（2026-10-20 追加）
- **背景**：star と galaxy の目視ラベルは境界で一致しない（galaxy ラベルの 31% が PSF と同じ大きさ、star ラベルの 13% がはっきり広がっている）。そこで「見かけ上、点源か広がっているか」を数値で決めることにした。
- **特徴量**（`host_morphology.py`）：カットアウトの FITS に入っている各画像自身の PSF（`PSFIMAGE`）と不確かさ（`UNCERT`）を使い、Template と Science のそれぞれで、PSF に対する大きさの比、開口と PSF のフラックス比、集中度の比、楕円率、PSF モデルの χ²、母天体の中心と突発天体の位置のずれ、PSF の FWHM、S/N を求める。観測日ごとのシーイングの違いは、その画像自身の PSF と比べることで打ち消す。全ソースの値は `data/cache/host_morph_step2_*.npz` にキャッシュする。
- **閾値**：基準の恒星（SIMBAD で恒星に分類されたもの、または Gaia DR3 の視差の S/N > 5、計 7,809 ソース）について、Template の大きさの比の分布を S/N の区間ごとに求める。95 パーセンタイル以下を `point`、99 パーセンタイルより大きいものを `extended`、その間を `uncertain`、Template の S/N が 10 未満のものを `low_snr` とする。閾値は `data/host_morph_thresholds_step2.json` に固定し、`--refresh_thresholds` で決め直す。
- **検証**：分光で確認済みの SN の母天体は 84% が extended、point は 0%（残りは S/N 不足）。基準の恒星は 95% が point、extended は 1%。SIMBAD の QSO / AGN は 84% が point。
- **`--step 2 --mode host_morph [--model_version s2_v1]`**
  - 全ソースを判定して `data/host_morph_step2.csv` に出力する。
  - `--model_version` を付けると、RF の判定（no_host / bogus はそのまま使う）と組み合わせた最終判定を `data/predictions_step2_<版>_hm.csv` に出力する。最終判定では、point を `star`、extended を `galaxy`、uncertain と low_snr を `uncertain` とする。RF の判定は `decision_rf` 列に残す。
  - この出力は `export_candidates_pdf.py --step2_csv` にそのまま渡せる。
- **天体単位の判定（既定、`--host_morph_level object`）**：Template は観測ごとに Science の座標へ再サンプリングされていて、PSF 画像も観測ごとに違う。そのため、同じバンドでも大きさの比が ±0.01〜0.015 ばらつき、観測ごとに判定すると閾値付近の天体が「1 回でも extended なら galaxy」になっていた。そこで次のようにまとめる。
  1. 観測ごとの大きさの比を、その S/N での閾値で規格化する（点源の上限 = 0、広がりの下限 = 1）。
  2. バンドごとに中央値をとる（観測数に依存しない）。
  3. 各バンドの値を、そのバンドの Template の S/N の中央値で重み付けして平均する（`host_score`）。
  4. 1 以上なら extended、0 以下なら point、その間は uncertain。使えるバンドが無ければ low_snr。
  - 天体単位では、分光で確認済みの SN の母天体の 93% が extended（point は 0）、恒星の extended は 1%、SIMBAD の QSO / AGN の extended は 17.9% から 12.4% に減った。
  - 出力の CSV には `host_score`、`band_scores`（バンドごとの値）、`host_morph_source`（観測ごとの判定）も残す。`--host_morph_level source` で観測ごとの判定に戻せる。
- **`export_candidates_pdf.py --include_host_morph uncertain,low_snr`**：`*_hm.csv` を使うとき、母天体の形の判定が uncertain / low_snr のために最終判定が uncertain になったソースも含める（超新星候補の完全性を上げるため）。並び順は galaxy、no_host、母天体の形が uncertain、low_snr の順。パネルのタイトルの 1 行目に `H:unc` / `H:lowSN` を付け、一覧の CSV には `host_morph`、`tmp_snr`、`tmp_size_ratio` 列を加える。

### 2.18 visit 単位の除外と、怪しい visit の報告（2026-10-21 追加）
- **除外リスト** `data/excluded_visits.csv`：現在は visit 2026011700646（z、2026-01-17）だけ。明るい恒星のすべてに、約 3.3 秒角ずれた「もう 1 つの像」があり、step1 で positive_real と判定された 3,656 件がすべて偽検出だった。
  - 追加は `--mode exclude_visit --visit <番号> --reason "<理由>"`。除外する visit のソースの一覧は `data/excluded_sources.csv` に作る。
  - 除外は DB と step1 の出力を変えずに行う：`aggregate_objects` で該当ソースの step1 の判定を bogus 扱いにする（step2 の入力からも外れる）。`host_morph` の最終判定でも bogus にし、`export_candidates_pdf.py` でも選ばない。
- **怪しい visit の報告** `--mode visit_check`（除外はしない）：
  - positive_real が多い上位 100 visit について、Template の中で最も明るい点の、中心からの方向と距離がそろっているか（`offset_consistency`）を調べる。0.5 以上なら「怪しい」として報告する。visit 2026011700646 は 0.98、それ以外は 0.06 以下だった。
  - positive_real の件数が多いだけの visit（43 個）は、参考として報告する。step1 は「同じ天体・同じ夜・同じバンドは最新の 1 件」だけを使うので、連続撮像の最後の visit に件数が集まる。小惑星の多い夜でも件数が増える。
  - 結果は `data/visit_quality_report.csv` に出力する。
- **母天体の形態特徴のキャッシュ**：step2 の入力が既存のキャッシュの一部になった場合（visit の除外などで）は、計算し直さずにその部分を使う。

### 2.19 グループ B 専用の分類（step 2b、2026-10-21 追加）
- **グループ分け**（`host_morph` の `host_group` 列）：
  - **A**：Template の中心から 1.5 FWHM 以内に極大があり（母天体の中心が突発天体の位置にある）、S/N が 10 以上。PSF との大きさの比で、star / galaxy / uncertain を決める。
  - **B**：それ以外。専用のモデルで 4 クラスに分ける。
- **4 クラスと最終判定の対応**：no_host → no_host、real_uncertain → uncertain、galaxy（大きな銀河の裾野）→ galaxy、bogus → bogus。
- **特徴量**：step2 の SimCLR（128）、step1 の SimCLR（128）、step1 の差分像の形態特徴（15）、母天体の形態と文脈の特徴（Template と Science）。文脈の特徴として `center_snr`（突発天体の位置での Template の S/N、PSF のマッチドフィルタ）、`brightest_snr`、`brightest_dist_fwhm`（視野で最も明るい天体）、`central_host` を、`host_morphology.py` の特徴量の版 2 で追加した。
- **ラベルとモデル**：学習用は `data/human_labels_step2b.csv`、評価用（グループ B から天体が重ならないように一様ランダム、ブラインド）は `data/eval_labels_step2b.csv`、モデルは `models/step2b/random_forest.joblib`、判定結果は `data/predictions_step2b.csv`。
- **判定画面**：タイトルに、突発天体の位置での Template の S/N と、最も明るい天体の S/N と距離を表示する。
- **コマンド**（`--step` の値は使わない）：
  - `b_seed`：既存の step2 のラベルのうち、グループ B に入る no_host / bogus / galaxy を取り込む
  - `b_eval_set [--eval_size 150]`：評価用セットを作る
  - `b_active_loop [--n_samples 20]`：能動学習を 1 サイクル回す（判定のあとで RF を学び直し、評価用セットで評価する）
  - `b_retrain`、`b_evaluate`：RF の学び直し、評価
  - `b_classify`：全件を判定する
- `host_morph` は、`data/predictions_step2b.csv` があれば、グループ B のソースの最終判定にそれを使う。

### 2.20 step2 の最終判定から従来の RF を外す（2026-10-21 追加）
- 最終判定は `data/predictions_step2_final.csv` に出力する（`group_b.write_final`。`host_morph` と `b_classify` の最後に実行される）。
  - グループ A：天体単位の母天体の形だけで決める（point → star、extended → galaxy、uncertain → uncertain）。
  - グループ B：4 クラスの RF（`data/predictions_step2b.csv`）で決める。まだ判定が無いものは uncertain（`decision_detail` = `B:no_model`）。
  - 除外した visit のソースは bogus。
  - 判定の内訳は `decision_detail` 列（`A:extended`、`B:galaxy` など）で分かる。
- 従来の 4 クラスの step2 RF（s2_v1）は使わない。`host_morph` の `--model_version` は無視し、`predictions_step2_<版>_hm.csv` は作らない。
- `export_candidates_pdf.py` の `--step2_csv` の既定値を最終判定のファイルにした。
  - 最終判定のファイルでは、`--include_uncertain` で uncertain（グループ A で形を判定できないもの、グループ B の real_uncertain、まだ判定が無いもの）も含める。
  - パネルのタイトルの 1 行目に `decision_detail`、3 行目に、グループ A なら host_score と Template の S/N、グループ B なら判定の確率と突発天体の位置での Template の S/N を表示する。

### 2.21 step1 の作り直しと、新しいデータ用のスクリプト（2026-10-22 追加）
- **問題**：固定した step1 の RF（v20261019）は、10/17 に作った埋め込みで学習されていた。その埋め込みを作ったエンコーダは、10/18 の `semi_supervised` の学習で上書きされて残っていなかったため、新しいデータには使えなかった（グループ B の RF も、step1 の埋め込みを特徴量に使っていた）。
- **作り直し**：
  - 今のエンコーダで、step1 の全件の埋め込みを作り直した（旧は `data/embeddings_step1.npz.bak_old_encoder_20261017`）。
  - step1 の RF を学び直し、同じ閾値（positive_real 0.55、negative_real 0.75）で v20261022 として固定した。評価用セットでの重み付き正解率は 0.923、positive_real の純度 0.933、完全性 0.875。
  - `aggregate_objects`、`host_morph` をやり直した。step2 の埋め込みも作り直し（エンコーダは同じ。旧は `.bak_20261022`）、グループ B の RF を学び直した（評価用セットでの正解率 0.897）。
- **`find_sn_candidates.py`**（本体は `stamp_classifier/sn_pipeline.py`）：
  - `freeze --version <名前>`：step1 の固定モデル、step2 のエンコーダ、グループ B の RF、母天体の形の閾値、移動天体と visit チェックの条件を、`models/sn_pipeline/<名前>/` にまとめて固定する。固定の前に、各エンコーダが RF の学習に使った埋め込みを再現できるかを、実際に計算して確かめる。
  - `run --db <DB名> --start <日付> --end <日付> --bundle <名前>`：指定した観測夜（dayObs、両端を含む）のデータに、step1 → visit チェック → 天体単位の集計（検出履歴、移動天体）→ step2 → 候補選択を行う。DB は読み取りだけ。
  - 出力：`candidates.csv`（1 天体 1 行。各バンドの期間内で最新の scienceFlux、誤差、MJD を含む）、`candidates.pdf`（candidates.csv と同じ順に、1 ページ 80 天体）、`all_sources.csv`、`visit_check.csv`、`run_info.json`。`--per_object_csv` で天体ごとの CSV も出力する。
  - 新しいデータでは、visit チェックで異常と判定された visit を既定で除く（`--keep_suspicious_visits` で残す）。判定条件は、方向のそろい具合 0.5 以上かつ、ずれの大きさ 5 ピクセル以上。
  - 天体単位の集計と母天体の形の判定は、指定した期間のソースだけで行う（検出履歴は DB 全体と prvDiaSources を使う）。

## 3. 使い方
```bash
# 評価用セットを作る (最初に 1 回。中断しても再開可)
bin/python stamp_classifier/run_pipeline.py --step 1 --mode build_eval_set --eval_size 150
# 少数クラスを層別に補強 (層の評価ラベルの目標件数を指定。初回に層を固定)
bin/python stamp_classifier/run_pipeline.py --step 1 --mode build_eval_set --eval_stratum negative_real --eval_size 60
bin/python stamp_classifier/run_pipeline.py --step 1 --mode build_eval_set --eval_stratum positive_real --eval_size 70
# 現在の RF を評価用セットで評価 (層ファイルがあれば重み付き)
bin/python stamp_classifier/run_pipeline.py --step 1 --mode evaluate
# 能動学習 (評価用セットでの精度が毎サイクル記録される)
bin/python stamp_classifier/run_pipeline.py --step 1 --mode active_loop
# SimCLR の再学習 (評価用セットがあれば holdout に使用)
bin/python stamp_classifier/run_pipeline.py --step 1 --mode semi_supervised [--supcon_mode mixed|separate] [--holdout_frac 0.2]
```

## 4. 未対応・今後の課題
- **能動学習のフィードバック**：デフォルトは今もラベル付きデータだけでの SupCon 微調整（`fine_tune`）。比較実験では SupCon に汎化への効果が無かったので、評価用セットができたら、微調整の有無で `eval_acc` を比べる。
- **real と bogus の境界**：誤りはすべて real と bogus の間で起きている（positive と negative は混同されない）。sci と template をチャネルとして加えることと、境界事例のラベルの見直しが候補。
- **評価用セットの規模**：ランダムに選ぶと `negative_real` が少なくなりやすい（200 件中 11 件）。層別の追加と重み付き評価（2.5 節）で補う。予測 bogus の層（約 41 万件）に混ざる少数クラスの割合の推定が、recall の誤差の主な原因として残る。
